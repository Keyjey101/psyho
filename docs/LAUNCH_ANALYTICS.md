# Запуск платного трафика: что построено и как этим пользоваться

Реализация ТЗ «подготовка сервиса к запуску платного трафика».

**Главная метрика этапа:** доля вернувшихся на следующий день (D1) в разрезе источника.
В админке это колонка **«Цена D1-возврата ₽»** — по ней принимается решение о повторной закупке.

> Примечание: в ТЗ указан стек админки Vue. Фактически проект на React 19 + Vite,
> вкладка аналитики сделана на React в стиле существующей админки.

---

## 1. Перед первым рублём в рекламу

Заполнить в `backend/.env` (см. `.env.example`):

```
SPEND_GUARD_ENABLED=true
DAILY_USER_TOKEN_LIMIT=120000        # жёсткий лимит токенов на юзера в сутки
DAILY_GLOBAL_SPEND_LIMIT_USD=20.0    # глобальный дневной потолок
ADMIN_ALERT_CHAT_IDS=123456789       # куда слать 50/80/100% (узнать у @userinfobot)
PUBLIC_BASE_URL=https://вашдомен
TELEGRAM_BOT_USERNAME=имя_бота
FAKE_DOOR_ENABLED=true
FAKE_DOOR_PRICE_RUB=390
CRISIS_EMERGENCY_SESSIONS=1
```

Без `ADMIN_ALERT_CHAT_IDS` лимиты работают, но уведомления не придут — в логах будет
`spend_alert_no_admin_chat`.

Миграция: `alembic upgrade head` (запускается автоматически в `start.sh`).

## 2. Как завести кампанию

Админка → вкладка **Аналитика** → блок «Кампании и ссылки» → кнопка «Кампания».

Код кампании: `[A-Za-z0-9_-]`, до 32 символов, например `tg_bezfiltrov_01`.

Сразу после создания в карточке появляются две готовые ссылки с кнопкой копирования:

| | Ссылка |
|---|---|
| Бот | `https://t.me/<bot>?start=tg_bezfiltrov_01` |
| Веб | `https://вашдомен/?utm_source=...&utm_campaign=...&c=tg_bezfiltrov_01` |

Для рекламы теста ссылку на веб можно вести на посадочную страницу теста:
`https://вашдомен/test/anxiety?utm_source=telegram&utm_campaign=bezfiltrov&c=tg_bezfiltrov_01`

**Затраты** вносятся в том же блоке — поле «Затраты ₽». Без них не считаются ни CPA,
ни цена D1-возврата (в таблице будет «—»).

## 3. Атрибуция

**First-touch и неизменяемая.** `User.campaign_code` пишется один раз при создании
пользователя. Единственная функция, которой это разрешено, — `attribution.apply_first_touch()`,
и она отказывается перезаписывать уже заполненное поле.

Пути входа:

| Вход | Что происходит |
|---|---|
| `t.me/bot?start=<code>` | Код резолвится по справочнику. Если аккаунта ещё нет — код паркуется в `pending_attributions` по telegram_id и «забирается» при регистрации |
| `t.me/bot?start=<другой код>` у существующего юзера | Атрибуция **не меняется**, пишется `repeat_start` |
| Веб с `utm_*` | UTM кладутся в localStorage на 30 дней **сразу при заходе**, до любых действий (`lib/analytics.ts`) |
| Веб → бот | `POST /api/bot-link` резолвит UTM в кампанию и отдаёт `?start=<code>` — в payload Telegram влезает только короткий код (64 символа, `[A-Za-z0-9_-]`) |
| UTM без кампании | Кампания создаётся автоматически с `origin=auto_created` — трафик не теряется, в таблице помечена бейджем `auto` |
| Payload пустой/битый | `organic` |

## 4. События

Таблица `events`, append-only: `id, user_id, anon_id, event_type, campaign_code, payload_json, created_at`.

**Тексты сообщений в аналитику не попадают ни при каких условиях.** Это не соглашение,
а механика: `events.sanitize_payload()` пропускает только ключи из белого списка
`_SAFE_PAYLOAD_KEYS` и режет строки до 128 символов. Если новый вызов передаст
`{"content": "..."}` — ключ будет отброшен, а не сохранён.

`user_id` — внутренний UUID. Telegram-id в события не пишется: до регистрации
используется солёный хеш (`anon_id`), который после регистрации сшивается с `user_id`.

Проверить можно прямо из админки: `GET /api/admin/analytics/privacy-check` возвращает
`violations: 0` и `ok: true`.

Клиент может отправлять только события воронки (`events.CLIENT_TRACKABLE`).
Попытка отправить `bot_start` или `crisis_detected` из браузера → 400.

## 5. Границы расходов

Два независимых потолка, оба **не связаны с кредитами**:

- **На пользователя в сутки** — `DAILY_USER_TOKEN_LIMIT` токенов. При превышении
  пользователь получает вежливое сообщение в чате и событие `user_token_limit_hit`.
- **Глобально в сутки** — `DAILY_GLOBAL_SPEND_LIMIT_USD`. При достижении
  **останавливается регистрация новых пользователей** (503 на всех путях авторизации).
  Существующие пользователи продолжают работать.

Уведомления админу в Telegram на 50% / 80% / 100% — каждое ровно один раз в сутки
(порог фиксируется в той же транзакции, что двигает счётчик, поэтому гонка невозможна).

Дашборд: админка → Аналитика → блок «Расходы на LLM» (сегодня, за месяц, % лимита,
статус приёма новых пользователей).

Сброс — в 00:00 UTC.

## 6. Кризисный сценарий

Решение о том, что результат «тяжёлый», принимается **на бэкенде**
(`services/test_safety.py`), а не в браузере — устаревший или изменённый клиент
не должен уметь спрятать кризисные контакты.

Два независимых триггера:

1. **Чувствительный пункт** — вопрос про суицидальные мысли/самоповреждение отвечен
   выше нуля. Для PHQ-9 это пункт 9. Срабатывает **даже при низком общем балле**.
2. **Тяжёлая зона** — балл выше порога `SEVERE_RATIO` для скрининговой шкалы.

При срабатывании любого:

- контакты живых служб рендерятся **выше и заметнее** CTA в бота (`CrisisResources.tsx`);
- CTA в бота становится визуально тише;
- **никакого предложения купить или потратить кредиты** — кнопка «Поделиться» и любые
  продающие блоки скрыты;
- в тексте нет диагнозов — только «результат опросника».

В диалоге: при срабатывании детектора сессия помечается `crisis_flagged`, и
fake-door для неё не показывается вообще. Если кредиты кончились в кризисной сессии —
выдаётся аварийный запас (`CRISIS_EMERGENCY_SESSIONS`), а не стена.

## 7. Fake door

При исчерпании кредитов бэкенд отдаёт 402 с `fake_door: true` и ценой.
Фронт показывает `FakeDoorModal`: реальная цена, реальный состав подписки, кнопка «Оплатить».

По нажатию — **не платёж**, а честный текст: оплата запускается в ближайшее время,
оставьте контакт, дадим бесплатный период. Никакой имитации оплаты, никаких полей карты.

Собранные контакты: админка → `GET /api/admin/analytics/waitlist`.

События: `credits_exhausted` (сервер) → `paywall_viewed` → `paywall_clicked` → `email_submitted`.

## 8. Приватность (152-ФЗ)

Перед первым сообщением показывается `ConsentGate`: явная плашка «ты общаешься с ИИ»
+ согласие на обработку персональных данных со ссылками на политику и текст согласия.
Факт согласия пишется на сервер (`users.consent_accepted_at`), а не во флаг localStorage.

Из интерфейса и рекламных материалов убраны «терапия», «лечение» в отношении сервиса
(школы переименованы в «подходы»). Слова «диагноз» и «лечение» остались только там, где
это дисклеймер — «это не диагноз».

## 9. Ручная приёмка

| # | Проверка | Как |
|---|---|---|
| 1 | `?start=test_campaign` → `bot_start` с этим кодом | Перейти по ссылке, посмотреть `events` |
| 2 | Второй код не меняет атрибуцию, есть `repeat_start` | Перейти по второй ссылке тем же аккаунтом |
| 3 | `/test/anxiety?utm_source=x&utm_campaign=y` → бот → атрибуция сохранилась | Пройти путь целиком |
| 4 | Все четыре события теста | Пройти тест до результата и нажать «Поделиться» |
| 5 | Исчерпание кредитов → `paywall_viewed` / `paywall_clicked`, форма работает | `MONETIZATION_ENABLED=true`, `FREE_LIFETIME_SESSIONS=1` |
| 6 | Кампания видна, затраты вносятся, CPA и цена D1 считаются | Админка → Аналитика |
| 7 | Кризисное сообщение → контакты показаны, fake-door нет | Тестовое сообщение в чате |
| 8 | Превышение дневного лимита → регистрация остановлена, уведомление пришло | Временно `DAILY_GLOBAL_SPEND_LIMIT_USD=0.001` |
| 9 | В `events` нет текстов сообщений | `GET /api/admin/analytics/privacy-check` |

Пункты 1, 2, 3, 4, 5, 6, 7, 8, 9 покрыты автотестами при разработке
(атрибуция, неизменяемость first-touch, лимиты расходов, санитизация payload,
математика CPA/D1, кризисное исключение) — но перед запуском их нужно прогнать
руками на живом боте, потому что реальный `/start` и Telegram-доставка автотестами
не воспроизводятся.
